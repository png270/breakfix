PROJECT INFORMATION
-------------------
Project: Break My Fix
Team: 0day
GitHub: https://github.com/png270/breakfix

Break My Fix is an autonomous AI security-testing agent that
reviews AI generated security patches, executes adversarial
tests, adapts based on test results, and determines whether
the vulnerability was actually fixed.

We are building two applications in ONE Git repository:

1. BookShelf (demo-app/)
   A small book-reviewing web application that will serve
   as the authorized and controlled security-testing environment.

2. Break My Fix (backend/ and frontend/)
   Our main AI agent and its dashboard, which we will
   implement AFTER BookShelf is complete.

PHASE 4 — IMPLEMENT BOOKSHELF
===========================================================

Build a small but polished web application called BookShelf.

CONCEPT:

BookShelf is a minimal Letterboxd-style application
for books.

Users can:
- Create an account.
- Log in.
- Customize their profile.
- Browse and search books.
- Open individual book pages.
- Leave text reviews.
- Read reviews written by other users.

TECHNOLOGY:

Backend:
- Flask

Database:
- SQLite using Python's sqlite3 module

Frontend:
- HTML
- CSS
- Flask's built-in Jinja2 templates

Authentication:
- Flask sessions
- Werkzeug password hashing

Do not use React for BookShelf.


FEATURE 1 — AUTHENTICATION

Implement:

- Signup page
- Login page
- Logout functionality
- Session-based authentication
- Password hashing using Werkzeug
- Basic form validation
- Error messages for invalid credentials

Never store plaintext passwords.

Use a development-only secret key supplied through
an environment variable, with a clearly documented
local development fallback.

Do not commit real secrets.

Profile fields:

PHASE 6 — PREPARE FOR FUTURE SECURITY TESTING
===========================================================

BookShelf is the controlled demo application for
Break My Fix.

Later, we will introduce two intentionally vulnerable
scenarios and use Codex to generate security patches.

SCENARIO A — SQL INJECTION

Attack surface:
Book search.

Future workflow:
1. Introduce a controlled SQL injection vulnerability.
2. Create a vulnerable baseline Git branch.
3. Ask Codex to fix the vulnerability.
4. Create a GitHub PR containing the fix.
5. Break My Fix analyzes the PR.
6. Break My Fix tests whether SQL injection is prevented.

Expected scenario:
The patch correctly fixes SQL injection.


SCENARIO B — STORED XSS

Attack surface:
Book reviews.

Future workflow:
1. Introduce a controlled stored XSS vulnerability.
2. Ask Codex to implement an intentionally incomplete fix.
3. Create a GitHub PR containing the patch.
4. Break My Fix analyzes the PR.
5. Break My Fix submits adversarial reviews.
6. Break My Fix uses Playwright to verify whether
   JavaScript executes when reviews are displayed.

Expected scenario:
The patch fails to prevent stored XSS.


IMPORTANT SECURITY REQUIREMENTS:

For this initial BookShelf implementation:

- Use secure defaults.
- Use parameterized SQL queries.
- Escape user-generated HTML.
- Do not introduce vulnerabilities yet.
- Do not disable Flask/Jinja2 security protections.
- Do not create security-fix branches or PRs yet.

Keep the application easy to test locally.

Later security-testing scenarios must be reproducible
and isolated from public production environments.
