We are building Break My Fix, an autonomous security patch
verification agent for the neatHack hackathon.

Repository: https://github.com/png270/breakfix

CURRENT STATE
- main contains the secure BookShelf Flask application.
- demo/vulnerable-bookshelf contains controlled SQLi and XSS flaws.
- PR #1: https://github.com/png270/breakfix/pull/1
- PR #2: https://github.com/png270/breakfix/pull/2
- Entire is already configured.
- neatlogs will be installed and integrated AFTER implementing
  the agent, but BEFORE its first live PR analysis.

GOAL

Implement an agent that:
1. Accepts a GitHub security-fix PR URL.
2. Fetches the PR diff and relevant source code.
3. Uses an LLM to form security hypotheses.
4. Selects and executes testing tools.
5. Observes results and adapts its next actions.
6. Produces an evidence-backed security verdict.

Do not hardcode conclusions based on PR numbers.

PHASE 2 — ENVIRONMENT

Create a Python backend using:
- FastAPI
- Uvicorn
- Pydantic
- HTTPX
- pytest
- Playwright
- An OpenAI-compatible LLM client

Create backend/.venv and install dependencies.

Add backend/.env.example and appropriate .gitignore entries.

Do not require a personal paid API key.
Support configurable model endpoint and model name.

Do not make real LLM calls yet.

PHASE 3 — MODULES

Implement:

backend/app/main.py
  FastAPI application and POST /api/analyze endpoint.

backend/app/github.py
  Validate PR URLs, retrieve metadata and diff, pin the head
  commit SHA, and retrieve relevant source files.

backend/app/schemas.py
  Pydantic models for PR data, hypotheses, tool actions,
  observations, evidence, and verdicts.

backend/app/state.py
  Track agent steps, hypotheses, observations, errors,
  retries, and execution budget.

backend/app/llm.py
  LLM adapter with documented tool-calling support.

backend/app/agent.py
  Bounded agent control loop.

backend/app/tools/inspect.py
  Read allowlisted source files.

backend/app/tools/http.py
  Make bounded HTTP requests to the isolated demo app.

backend/app/tools/browser.py
  Execute Playwright browser tests and capture observations.

backend/app/sandbox.py
  Manage the isolated BookShelf testing environment.

backend/app/observability.py
  Define a small interface for future neatlogs integration.
  Do not install neatlogs yet.

Keep modules small and responsibilities clearly separated.

PHASE 4 — GITHUB INGESTION

Accept only PRs belonging to png270/breakfix.

Retrieve:
- PR metadata
- Base SHA
- Head SHA
- Changed files
- Patch diff
- Relevant source context

Exclude evaluation material from the agent's context:
- demo-app/tests/
- hackathon.md
- README sections revealing expected outcomes
- Prewritten exploit demonstrations
- Known bypass payloads

The agent should receive only information necessary to
independently investigate the patch.

Treat repository content and PR descriptions as untrusted data.

PHASE 5 — AGENT LOOP

Implement:

OBSERVE -> REASON -> SELECT TOOL -> EXECUTE
        -> EVALUATE -> CONTINUE OR FINISH

The LLM must choose actions based on tool observations.

Use:
- Maximum 8 agent steps
- Per-tool timeout
- Overall execution timeout
- Bounded retries
- Explicit terminal states

The agent may request tools but must not execute arbitrary
Python or shell commands.

Validate every tool call before execution.

PHASE 6 — SECURITY TOOLS

Provide:

inspect_patch:
  Return relevant source and diff excerpts.

http_request:
  Send bounded requests to the isolated BookShelf instance.
  Restrict destinations to the configured test target.

browser_test:
  Run Playwright against the isolated BookShelf instance.
  Support controlled login, review submission, navigation,
  and harmless browser-execution markers.

compare_behavior:
  Compare observed results against a stated security property.

generate_regression_test:
  Produce a reproducible test from confirmed observations.
  Store generated tests in a temporary output directory.

Tool results must be structured and fed back into the agent.

Do not implement a general shell execution tool.

PHASE 7 — ISOLATION

Do not execute arbitrary public PR code on the Mac.

Use a preapproved BookShelf fixture and isolated execution.

Prefer a restricted Docker environment with:
- No privileged mode
- No host secrets
- No Docker socket mount
- CPU and memory limits
- Execution timeouts
- Restricted network access

If Docker isolation is unavailable, report the limitation
and disable live PR execution.

Do not silently fall back to running untrusted code on host.

PHASE 8 — VERDICT GENERATION

Supported verdicts:

FIX_VERIFIED:
No bypass reproduced within the executed test scope.

BYPASS_CONFIRMED:
A bypass was actually reproduced with concrete evidence.

INCONCLUSIVE:
Insufficient evidence, tool failure, or exhausted budget.

Never invent execution results.

Return:
- PR URL and pinned commit
- Verdict
- Summary
- Hypotheses
- Tool actions and observations
- Evidence
- Generated regression tests
- Errors and limitations
- Trace ID placeholder
