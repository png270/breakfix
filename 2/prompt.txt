BACKGROUND

Break My Fix is an autonomous AI security-patch verification agent.

The agent runs two approved, immutable BookShelf fixture images corresponding to:
- SQLi PR #1: b0b635eba99f24a3641f729c1a95864a2ee36c9d

ROOT CAUSE — EXPERIMENTALLY VERIFIED

The browser currently launches with:

    playwright.chromium.launch(
        headless=True,
        chromium_sandbox=True
    )

The fixture container uses:

    --network=none
    --read-only
    --cap-drop=ALL
    --security-opt=no-new-privileges
    --user=10001:10001
    --cpus=1
    --memory=768m
    --pids-limit=128

Chromium fails with:

    FATAL: zygote_host_impl_linux.cc:129
    No usable sandbox!

We independently reproduced the failure using the approved Docker image.

We then tested user-namespace creation:

    os.unshare(os.CLONE_NEWUSER)

Results:

1. Docker default seccomp profile:
   PermissionError(1, 'Operation not permitted')

2. Same container restrictions with:
   --security-opt=seccomp=unconfined

   USER_NAMESPACE_CREATED

Therefore, Docker's default seccomp profile is blocking
the user-namespace operation Chromium requires.

IMPORTANT:
seccomp=unconfined was ONLY used for a controlled diagnostic.
It must NOT become the permanent configuration.

OBJECTIVE

Make Playwright Chromium launch successfully with:

    chromium_sandbox=True

while preserving strong isolation of the vulnerable BookShelf
application and the host.

PREFERRED ARCHITECTURE

Separate the application fixture and browser execution
into two isolated containers.

Container A: BookShelf fixture
- Runs the approved immutable BookShelf application.
- Retains strict seccomp restrictions.
- Retains non-root execution.
- Retains read-only filesystem.
- Retains dropped Linux capabilities.
- Retains no-new-privileges.
- No host mounts, Docker socket, or secrets.
- No unrestricted outbound network access.

Container B: Playwright browser worker
- Runs Chromium as a non-root user.
- Uses a narrowly scoped Chromium-compatible seccomp profile.
- Keeps chromium_sandbox=True.
- Retains resource limits, read-only filesystem where feasible,
  dropped capabilities, and no-new-privileges.
- Has no host mounts, Docker socket, or application secrets.
- Can communicate ONLY with the approved BookShelf fixture
  over a controlled internal network.
- Must not have unrestricted internet access.

Use official Playwright Docker guidance for Chromium sandboxing
as a reference.

SECURITY DESIGN REQUIREMENTS

1. Do not use seccomp=unconfined in the final implementation.

2. Do not set chromium_sandbox=False or pass --no-sandbox.

3. Do not use --privileged.

4. Do not expose BookShelf ports to the Mac host.

5. Do not mount the Docker socket or host directories.

6. Do not automatically build, pull, or execute unreviewed
   GitHub PR source code.

7. Preserve immutable image approvals and commit attestation.

8. Preserve the existing bounded tool interface.
   The model must not be able to execute arbitrary commands,
   Python, JavaScript, or shell scripts.

9. Preserve the browser tool's restrictions on navigation,
   downloads, service workers, and execution time.

10. Prevent the browser from reaching the host, Docker daemon,
    metadata services, or arbitrary external addresses.

11. Do not modify, merge, or close either existing GitHub PR.

12. Do not change the intended SQLi or XSS vulnerabilities
    in the demo fixtures.
